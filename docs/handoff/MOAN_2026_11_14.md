# Moan, round 171: timeline and mixer engine

Moan is the planned audio workstation. This first slice is `crates/moan-core`, a
GPL-3-only, no_std + alloc engine, and `apps/moan-probe`, a guest proof program.
There is no DAW window yet: the shared Weft toolkit is in open PR #220.

## Engine contract

- Immutable borrowed stereo i16 sources, all at 48 kHz. Positions and lengths are
  frames, not samples or milliseconds. Convert other rates before insertion.
- Non-destructive split and trim. Trim keeps the retained audio's timeline position
  and removes fades. Split preserves outer fades, clamped to each new clip length,
  and leaves the new inner edges unfaded. This can change an envelope crossing the
  cut; it is explicitly not a promise to preserve a faded split's waveform.
- Clip gain and track volume, each 0..400%; linear stereo balance -100..100,
  centre unity. Mute and solo; muted solo tracks do not suppress other tracks.
- Overlapping clips sum. Render fills a caller-owned block without allocating,
  accumulates before PCM clipping and returns silence outside clips. Block size
  does not change output. Source memory remains the caller's responsibility.
- Linear fades include a silent endpoint and reach unity at frame length-1. A
  one-frame fade is silent. Overlapping fade-in/out envelopes multiply.

## Validation

`scripts/moan_host_gate.sh` runs ten timeline/mixer integration tests.
The guest compiles for `x86_64-sex-app.json` and passes `scripts/key_bytes.py`.

`scripts/moan_gate.py --iso sexos-v1.0.0.iso --source-disk BLANK.img --out OUT`
installs `moan-probe` on a copied disk, runs it from Spindle, and records Bell's
virtio-snd output. The probe splits a source, applies gain, volume, fades and
opposite pans, and sends 96,000 frames through its own sound ring. The gate checks
both channels for two seconds of 400/600 Hz, amplitude and dropouts; `result.json`
and the WAV are retained by the Programs CI job. The QEMU result must pass before
merge; a successful compile alone does not establish playback.

## Round 172: per-track effects

`effects::Rack` holds optional EQ, compressor and reverb in that order. An empty
rack bypasses samples exactly. Configuration allocates only when creating reverb
(about 124 KiB); processing and reset do not allocate. All DSP uses bounded integer
arithmetic, at 48 kHz, with headroom before final PCM clipping.

- EQ: three bands, nominal 200/4000 Hz one-pole crossovers, 0..400% per band.
  Residual bands make flat unity gains reconstruct the original signal exactly.
- Compressor: stereo-linked peak detector, threshold 1..32767, ratio 1..20,
  attack/release smoothing divisors 1..480000 frames. No lookahead, makeup gain or
  soft knee; slow attacks intentionally pass transients. Ratio 1 bypasses gain.
- Reverb: four parallel feedback combs and two serial allpasses, fixed delay lengths,
  feedback 0..90%, wet 0..100% added to dry. It is a small algorithmic reverb, not
  convolution or a model of a particular room.

`render` remains the stateless dry renderer. `render_processed` runs each track's
rack before its volume and pan. Render sequential blocks to preserve history;
pausing makes no calls. A discontinuous playhead resets all racks, while an empty
render changes nothing. Muted/non-solo tracks advance DSP without entering the mix.
Continue rendering beyond clip ends to drain tails; call `Track::reset_effects`
after edits or project changes when tails should be discarded. Standalone rack
processing requires the caller to reset when starting a new stream.

There are 21 host integration tests. `scripts/moan_host_gate.sh` also renders a
reference WAV on the host and qualifies the effects waveform checker against it.
`moan-probe fx` in QEMU plays one second of compressed signal followed by silence;
`scripts/moan_gate.py --effects` checks stereo pitch, the lower peak, a nonzero
reverb tail after source audio ends, and decay. The host reference is not evidence
of guest playback; that claim still requires the QEMU gate to pass in CI.
