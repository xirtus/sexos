# 2026-11-18: `hw`, the hardware report for a PC with no serial port

- The kernel keeps the boot log's first 256 KiB whole (`console::log_head`), next to
  the 64 KiB ring the stop screen uses. `SYS_CRASH_LOG` gains `OP_LOG_HEAD` (6): Files,
  Shell and Spindle read it in 1 KiB chunks (`sex_pdx::crash_log::log_head`). ABI
  change: new op on syscall 85, no change to the existing ones.
- Spindle `hw` shows the hardware lines of that head (device census, VMD, NVMe drive and
  namespace, RAID, IOMMU, Intel display, GPU power, sound, network, USB, ACPI, Wi-Fi),
  newest 160 when there are more. `hw TEXT` shows the lines containing TEXT, `hw all`
  everything. One photo of Spindle is the hardware report on the Alienware x17 R1, whose
  on-screen boot log ends when the desktop starts.
- Gate: `scripts/nvme_real_drive_gate.py` runs `hw` and expects the drive and census lines.
- Runbook for the first x17 start: `docs/handoff/X17_BARE_METAL_RUNBOOK_2026_11_18.md`.
- Boot menu entry **"SexOS safe start"** (`CMDLINE=safe`, kernel `safe_start()`): the
  same system without dGPU power-off, IOMMU, MSI/MSI-X, and without leasing Wi-Fi, sound,
  touchpad (Serial IO) or the Intel display registers. Logs `[kernel.safe_start]`, and
  `[devmgr.lease.skip] ... reason=safe_start` / `[gpu.power] ... reason=safe_start`.
  `scripts/tests/test_limine_iommu_entry.py` keeps it equal to the main entry plus `safe`.
- `hw save [PATH]` writes the same report as a text file (default `hw-report.txt` in the
  working directory): every hardware line, then the newest 200 lines of the head. On the
  x17, `cd /media/NAME` on a second FAT/exFAT stick first, so the report leaves as a file
  instead of photos. Logs `[spindle.hw.save] lines= bytes= head_bytes=`. Spindle's file
  client gains `start_write_with` (write a generated buffer, up to 64 KiB). The NVMe gate
  saves the report and reads it back.
