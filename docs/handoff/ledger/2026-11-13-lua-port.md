# Lua 5.4 interpreter as an ordinary program (slice I7, part)

**`apps/lua`.** The official Lua 5.4.7 interpreter now runs on SexOS as `run lua ...`. The source is vendored unmodified under `vendor/lua-5.4.7/src`. It is MIT licensed, and the notice is at the end of `lua.h`. It came from the `v5.4.7` tag of github.com/lua/lua, because www.lua.org was not reachable from the build host. The test-only `ltests.*` and `onelua.c` are not vendored.

The app builds the same way `apps/chello` builds C: `build.rs` compiles the 33 sources with clang against musl's headers, with `-Dmain=sex_c_main`, and `src/main.rs` hands `argv` to `sex_libc::posix::run`. All of the following is built:
- the core
- the standalone `lua.c` front end, including `-e`, script files with `arg`/`...`, `-v`, `-i` and the interactive REPL on stdin
- every standard library: base, package, coroutine, string, table, math, utf8, io, os and debug

Lua is built in its plain ISO C configuration, with no `LUA_USE_POSIX` and no `LUA_USE_LINUX`, and with `LUA_COMPAT_5_3`.

**Registration** (one line or stanza in each list):
- the workspace `Cargo.toml`
- `sexos_build_spec.toml`: the whitelist entry and the `build_lua` stage, which writes `iso_root/programs/lua`

**`crates/sex-libc` additions** (userspace C library only, with no kernel or service change):
- `setjmp`/`longjmp` (plus `_setjmp`, `_longjmp`, `sigsetjmp`, `siglongjmp`): naked x86-64 assembly on musl's `__jmp_buf` layout. Lua's errors, `pcall` and coroutine error unwinding rely on these.
- `<ctype.h>` functions: `isalnum`, `isalpha`, `iscntrl`, `isdigit`, `isgraph`, `islower`, `isprint`, `ispunct`, `isspace`, `isupper`, `isxdigit`.
- `setlocale` and `localeconv`. There is one C/UTF-8 locale, and any other name is refused with NULL.
- `strcoll`, which compares bytes.
- `strerror`, which now returns musl's text for the common errnos instead of "error".
- `gmtime`, `localtime` and `difftime`.
- `strftime`, which now handles every C99 conversion (`%a %A %b %B %c %x %X %p %e %I %r %R %D %u %w %U %W %C %z %Z %n %t`, plus E/O modifiers) instead of the numeric fields only. Lua's default `os.date()` uses `%c`. A host test was added.
- On the ordinary-program target (`posix.rs`):
  - `tmpnam`: unused `tmpXXXX` names in the program's folder.
  - `tmpfile`: removed when the stream is closed.
  - `system`: `system(NULL)` returns 0 because there is no shell. A command fails with ENOSYS.
  - `signal`: the handler is accepted and never called, because nothing sends a program signals.
  - `raise`: ends the program with status 128+sig.

**Gate** (`scripts/lua_gate.py`, CI step "Lua 5.4 interpreter" after "Ordinary Rust and C programs"). It installs `lua` onto a blank disk and types five runs into Spindle. Its typer covers shifted punctuation (`( ) ^ " { } # % * < > ~ ...`) and capitals, and waits for Spindle to echo each key (`[spindle.input.recv] key=printable ch=X len=N`), because a burst of keys lost a shift release in the first try.
1. `-e print(2^100)` must print `1.2676506002282e+30`.
2. A tables, sort with a comparator, coroutine and `string.format` chunk, written with `io.write`.
3. A chunk that tests:
   - writing `t.lua` with `io.open`, then reading it back
   - `os.date('!%Y-%m-%d',86400)`
   - string methods
   - `pcall(error,'boom')`
4. `run lua t.lua x y` runs that script with its arguments. `os.time()` must be within 10 minutes of the host's clock.
5. `-e "error('bad')"` must put the message on `[std.err]` and exit with status 1.

**What doesn't work, and why:**
- `io.popen` reports "'popen' not supported". This is Lua's own ISO C fallback, because SexOS has no processes or pipes.
- `os.execute(cmd)` returns nil plus "Function not implemented", and `os.execute()` returns false because there is no shell.
- `require` of C modules reports "dynamic libraries not enabled", because there is no `dlopen`. Pure-Lua modules load through `package.path` (`./?.lua` etc.) from the program's folder.
- Ctrl-C does not interrupt a running chunk, because there are no signals.
- `os.getenv` always returns nil, because there is no environment.
- `os.tmpname` and `io.tmpfile` files live in the program's own folder. There is no shared `/tmp`.
- `string.format('%a')` prints decimal exponent form. sex-libc's formatter has no hex-float output yet.
- Local time is UTC, as everywhere in sex-libc.
