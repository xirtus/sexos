# Leak gate, kernel heap counters and Swatch (WS2, part 1)

- SYS_STATS (syscall 87) gains `OP_KERNEL` (5): kernel heap bytes in use, bytes
  mapped, live heap blocks, peak bytes, and the machine's free frames
  (`sex_pdx::system_stats::kernel()`). Read-only numbers, open to any task, like the
  other SYS_STATS ops. ABI change: a new op on an existing syscall; r9 now carries a
  fifth result.
- Swatch (`spawn swatch 1`, apps/hum/src/bin/swatch.rs): a background program that
  writes one `[swatch.sample]` record of those numbers plus free program memory and
  the pages program rows hold, then ends.
- `scripts/leak_gate.py`: opens and closes the fifteen most used programs (warm
  cycle, sample, four cycles, sample) and, with `--services` on a crash-probe image,
  stops and restarts Files, Network, Bell, Input, Shell and Display the same way.
  Any loss of free frames, kernel heap blocks/bytes or program-row pages over the
  tolerance is a leak; all leaks are listed in `leak.json`. Runs in CI as the
  `leaks` job, outside `build`'s required set until the leaks it finds are fixed.
- Removed dead code: `crates/silkbar` and `crates/tatami` (never-freeing bump
  allocators in crates no build used; the real SilkBar is `servers/silkbar`, the
  real Tatami `apps/settings` on sex-app's talc heap) and the unused
  `kernel/src/slab.rs`. Kernel: net about -55 lines.
- `scripts/tests/test_no_bump_allocators.py` forbids a never-freeing heap under
  servers/, apps/ and crates/ (null "no heap" allocators are fine); apps/qupid stays
  allowed until WS7 retires it.
