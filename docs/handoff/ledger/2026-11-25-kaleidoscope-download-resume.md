# Kaleidoscope validated download resume

- Network-truncated downloads or window closes with a strong ETag now sync their hidden `.part` and a bounded metadata record. A later exact-URL retry, including after restarting Kaleidoscope, requests `Range` with `If-Range` and appends only after an exact matching 206 status, ETag, `Content-Range`, identity encoding, and remaining length. Escape remains an explicit cancel that deletes the part.
- A changed or unsupported range reply discards the old part and starts from byte zero. Weak ETags, Last-Modified alone, private-tab URLs, and unvalidated partials never enter persistent resume metadata. Completed files still pass the existing staged sync/rename/sync promotion and completed history checks.
- Host tests exercise matching/mismatched responses and bounded record encoding. The browser QEMU gate interrupts a versioned body, restarts the browser, resumes to a checked hash; it also closes during a live transfer and resumes from the exact kept offset. A changed server ETag and bytes must produce a final visible file hash of only the new version. Kaleidoscope re-reads visible files up to 64 MiB after promotion before reporting download success. The gate captures `browser-download-resumable.ppm` and `browser-download-resumed.ppm`.
- A process killed before a transfer records confirmed resume metadata can leave an orphan hidden `.part`; it is never promoted or joined without a matching record. Full build and QEMU verification run in GitHub CI.
