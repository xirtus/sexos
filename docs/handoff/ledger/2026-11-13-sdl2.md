# SDL2 for SexOS programs (slice I8)

**`crates/sex-sdl` and `apps/sdltest`.** A C program can now use SDL2 on SexOS. It gets a window with a pixel surface, keys and pointer as SDL events, sound through SDL's audio API, and SDL timers and threads.

SDL 2.30.9 (zlib licence, `LICENSE.txt`) is vendored unmodified under `vendor/SDL2-2.30.9`. It came from the `release-2.30.9` tag of github.com/libsdl-org/SDL. Only the files this configuration compiles are vendored:
- `include/`
- the core, events, video (with yuv2rgb), render plus the software renderer, audio, stdlib, libm, atomic, cpuinfo, timer/unix, thread/pthread and generic semaphores
- the dummy filesystem, loadso, locale and misc stubs
- the haptic and sensor stubs, and the `core/linux` + `core/unix` headers that `SDL.c` includes

## How it is built

`crates/sex-sdl/build.rs` compiles about 150 sources with clang against musl's headers, in parallel, into `libSDL2.a`. It uses the same flags as apps/lua. It first copies SDL's headers to `OUT_DIR/include` (and `include/SDL2`), with `crates/sex-sdl/c/SDL_config.h` in place of SDL's own configuration, and passes that folder on as `DEP_SDL2_INCLUDE` (`links = "SDL2"`). The dynamic API is off (`DYNAPI_NEEDS_DLOPEN` without `HAVE_DLOPEN`).

The configuration in `c/SDL_config.h`:
- `HAVE_LIBC` plus the functions sex-libc exports (malloc, string functions, maths, stdio, `clock_gettime`, `nanosleep`).
- Threads: `SDL_THREAD_PTHREAD` on sex-libc's pthreads, which are the program's workers. Semaphores are SDL's generic ones.
- Timers: `SDL_TIMER_UNIX`.
- Off: joystick, haptic, sensor, HIDAPI, loadso, power, OpenGL/EGL/Vulkan. Filesystem, locale and misc are stubs.

## The backends (`crates/sex-sdl/c`, GPL-3.0-only)

The backends take the slots of SDL's dummy drivers (`DUMMY_bootstrap`, `DUMMYAUDIO_bootstrap`), so `SDL_video.c` and `SDL_audio.c` stay unmodified. SDL reports both drivers as `sexos`. They call small Rust `extern "C"` shims in `crates/sex-sdl/src/lib.rs` over `sex_std::window()` and `sex_app::sound::Sound`.

- **Video** (`SDL_sexosvideo.c`): one window per program. `SDL_GetWindowSurface` is the window's pixel area itself, as XRGB8888, when it fits. Otherwise it is a heap copy. `SDL_UpdateWindowSurface` calls `show_pixels(w, h)`, and the record gets `[sdl.present] n= w= h=` for the first four frames, then one frame in a thousand. The software renderer (`SDL_CreateRenderer`) works on top of this surface. The display mode is the window's pixel area.
- **Events**: `SDL_PumpEvents` drains the window. Keys arrive from Shell as presses only, with the shift and control held at the time, so each one becomes:
  1. a modifier press, if any
  2. `SDL_KEYDOWN`
  3. `SDL_TEXTINPUT`, for typing keys
  4. `SDL_KEYUP`
  5. a modifier release, if any

  Codes map through SDL's Linux table: set-1 and Linux codes agree below 0x59, and Shell's normalised movement keys are Linux's codes. Pointer events become mouse motion, buttons and wheel. Close becomes `SDL_WINDOWEVENT_CLOSE` and then `SDL_QUIT`. Each key is recorded as `[sdl.key]` and each close as `[sdl.close]`.
- **Audio** (`SDL_sexosaudio.c`): the device is always S16 stereo, at the asked rate clamped to 8000..192000 Hz. Bell resamples it. SDL's mixing thread copies each buffer into the sound ring and keeps about two buffers ahead of what Bell has taken, so `SDL_GetQueuedAudioSize` follows playback. On close, queued frames play out (for up to 3 s), and the record gets `[sdl.audio] rate= frames= nonsilent=`.
- **Stubs** (`SDL_sexosstubs.c`): `sigemptyset`, `sigaddset`, `pthread_sigmask`, `pthread_setcanceltype`, `pthread_get/setschedparam` and `sched_get_priority_min/max`, which SDL's pthread backend calls. They live in the SDL library. No sex-libc change was needed.

## apps/sdltest

`run sdltest [SECONDS]` does the following:
1. `SDL_Init(VIDEO|AUDIO|TIMER)`.
2. Draws a 320x240 window: red, green, blue and yellow quarters and a white middle, with `SDL_FillRect` and `SDL_UpdateWindowSurface`.
3. Reads back pixels and prints them.
4. Times `SDL_Delay(100)`.
5. Queues one second of 440 Hz at 48 kHz stereo (`SDL_OpenAudio`, `SDL_QueueAudio`, `SDL_PauseAudio(0)`) and waits for the queue to drain.
6. Waits for a key (120 s by default), printing the SDL events it gets.
7. Quits with status 0.

## Registration

The registration appends to each shared list:
- the workspace `Cargo.toml` members (`crates/sex-sdl`, `apps/sdltest`) and `Cargo.lock`
- `sexos_build_spec.toml`: the whitelist entry and the `build_sdltest` stage, which writes `iso_root/programs/sdltest`
- `.github/workflows/ci.yml`: the step "SDL2 program (video, sound, keys)" after "Lua 5.4 interpreter"

## Gate (`scripts/sdl_gate.py`)

QEMU gets an Intel HD Audio card whose output is recorded to `sound.wav`. The gate installs `sdltest` on a blank disk and types `run sdltest` into Spindle. It then checks:
- **The report:** the `[sdltest]` lines show SDL 2.30.9 with the `sexos` drivers, the expected pixel values, a delay of 100–200 ms, a queue of 192000 bytes that drains to 0, and `[sdl.audio]` with at least 48000 non-silent frames.
- **The window:** a screendump of the window tile (`[shell.tile.apply]`, with the program's pixels at +8/+36) is sampled at 9 points per quarter and in the middle, against the drawn colours.
- **The key:** K is pressed in the focused window. It must arrive as KEYDOWN with scancode 14 (`K`), then TEXTINPUT `k`, then KEYUP. Then `[sdltest] done` and `[std.exit] ... status=0`, and F11 retires the window.
- **The card output:** the WAV must hold a stretch of 0.8–1.3 s at 440±9 Hz.

## What doesn't work yet

- Only one window per program. The SDL window keeps the size it was created with. A smaller pixel area cuts it off, and a resize from Shell is not passed on as an SDL resize.
- There are no key-repeat or key-release timings: Shell sends presses only, so each key is a press immediately followed by its release. Shift and control are synthesised around the key. Alt, GUI and Caps Lock are not reported.
- No OpenGL or Vulkan, no joysticks, no `SDL_LoadObject`, no `SDL_GetBasePath`/`SDL_GetPrefPath` (dummy), no clipboard, no audio capture.
- `SDL_SetThreadPriority` succeeds and does nothing.
- No SDL game is ported yet.
