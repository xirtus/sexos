# Vellum detached CMS envelope

- `vellum-edit::cms` builds detached `SignedData` for exact `/ByteRange` slices. It hashes the two slices incrementally with SHA-256, canonicalizes signed attributes, and asks a callback to sign only the DER attribute set. Vellum does not receive the private key.
- The builder extracts issuer, serial and a P-256 public point from bounded X.509 DER, and refuses a mismatch with Shibari's public point. It does not validate certificate chains or PDF signing permissions.
- Focused host tests sign with Shibari, verify the resulting CMS independently with OpenSSL, reject changed content and malformed/mismatched certificates. A composition test embeds CMS into the PDF signature slot, reopens it with lopdf, and has OpenSSL verify the exact stored ByteRange. The fixture certificate is self-signed and its test scalar is not a production key.
- The Documents QEMU gate asks that host test to write its signed PDF fixture, fetches those exact bytes into SexOS, opens them in Vellum, checks `fields=1 signed=1 malformed=0 verified=0`, and captures `pdf-cms-signed-inspection.ppm`. This proves the guest reads the module's output, while explicitly showing that it does not verify identity or content. No guest signing operation or user-facing signing claim is made until the PDX service, certificate workflow and UI are wired. Full CI runs on GitHub only.
