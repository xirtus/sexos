# Denim D3: restart, worker faults, a store that gives memory back, 2x RAM

Compressed RAM (docs/handoff/COMPRESSED_RAM_PLAN_2026_11_14.md, slice D3), week plan WS1.

- **Denim restarts.** Denim is now a restartable BOOT service (`service_restart`, 7 slots).
  A new run's first call, `denim::RESET` (SYS 88 op 4), ends every program run that had
  pages out, since they were in the old run's store: the run ends as a forced run does
  (a task parked on such a page with it), gets a crash record ("compressed memory lost"),
  and the Shell hears `OP_LOST` (0x3D3) and shows a System notice naming the program
  (`servers/silk-shell/src/denim_notice.rs`). The old store's frames all go back.
  Spindle `crash denim` (probe builds) ends Denim as a fault would.
- **Workers.** A worker that touches a page Denim holds parks and comes back through
  Denim like the main task: the kernel finds the faulting task by its token
  (`FaultSlot::holds`, `program_workers::find`). Runs with workers may now have pages out;
  a worker spawn no longer recalls every page. Code (SEAL/OPEN) and VM loans still do.
- **Store.** Slabs live in pages of Denim's arena that can be given back one by one
  (`RETURN`, op 5) and refilled later (`REFILL`, op 6) — holes, used before the arena
  grows. When over an eighth of slab bytes sit unused, blocks move out of the sparsest
  pages into fuller ones and the emptied pages go back (compaction).
- **Clock hand and pace.** The scan is a clock hand over all runs, from where it
  stopped. Normal: every 2 s, aging only. Low: every 0.2 s, up to 8192 pages out per
  round. Critical: every round (~64 ticks), up to 16384, one cold pass enough.
- **Recall.** Once pressure is normal and free memory is over twice the low mark, pages
  come back 1024 per round.
- **Gates.** `scripts/denim_gate.py` (eager probe build) now also crashes Denim with a
  run's pages out and checks the run ends, the Shell names it and the run retires.
  `scripts/denim_double_gate.py` (ordinary build): heaptest `D` fills three times (plus 128 MiB) the memory
  free at its start (zeros, filled runs, text, an eighth noise), waiting while memory is
  critical, then reads every page back. CI job `denim-double` runs it at 1G and 12G.

ABI: SYS 88 ops `RESET`/`RETURN`/`REFILL`, message `OP_LOST` to the Shell.

Audit S9 (worker churn): a row keeps at most `MAX_WORKERS` + 8 worker tasks. Tasks are
reused, never freed, so once that many exist a spawn returns RETRY (the SDK yields and
asks again) until a dead one has waited out its 4 ticks, instead of taking a new 64 KiB
kernel stack every time.
