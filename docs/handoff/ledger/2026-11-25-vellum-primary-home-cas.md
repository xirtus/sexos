# Vellum: primary and encrypted-home conditional signed save

Vellum's signed PDF save previously read the destination and then renamed its staged replacement in a separate Files request. A writer between those calls could be overwritten. Files now accepts a complete expected SHA-256 digest with a staged source and destination, checks both paths against the caller's grants, and compares the destination before promotion in the same Files request. SexFS checks and renames in one guarded turn and commits the replacement. For a `/home` destination, Files copies the staged bytes into an internal encrypted-home stage, then performs the digest check and rename in one home commit. A failed check rolls the stage back; it never becomes a durable hidden file on its own. Vellum removes its app-folder stage after success or failure.

The `sexfs` host regression writes different bytes of the same length between the expected digest and promotion, proves `STALE` preserves both files, then checks a successful replacement after reopening the filesystem. Two home-style regressions check that a power cut before promotion and a stale destination leave the old PDF with no hidden stage. All three focused standalone tests passed after this review. The PDF QEMU gate now signs and reopens an encrypted-home PDF and captures its approval view; full guest execution and the screenshot are pending exact-head GitHub CI. Writable removable volumes answer `UNSUPPORTED` before modifying either file because their current FAT/exFAT rename paths cannot replace an occupied name in one durable transaction.
