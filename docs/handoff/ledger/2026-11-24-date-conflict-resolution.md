# Date CalDAV conflict resolution

- Date's conflict review now offers L for the retained local event and S for the current server event. Enter commits; Esc cancels the pending choice. A missing server event cannot be overwritten from this review.
- Choosing local preserves the current resource address and entity tag and marks the event Modified for the next CalDAV sync. Choosing server removes only the retained local note. Date stages and syncs the complete calendar file before replacing its in-memory copy; an unconfirmed save leaves the review open for a retry.
- A focused host test covers both choices, missing-server refusal, server identity and source immutability. The CalDAV QEMU gate resolves a real conflict, syncs the local choice, verifies the server received it and captures `date-conflict-local-choice.ppm`.
- The two-step local choice is not part of Ctrl+Z history, because it changes a synced resource. Another server change before the next sync may produce another conflict. Full build and QEMU screenshot verification run on GitHub CI.
- Conflict notes now persist the source calendar ID and CalDAV resource address. Local resolution requires both to match the current server copy, so a duplicate UID in a different calendar cannot be overwritten. Older notes without source identity can still be discarded with the server choice but cannot replace a server event.
- A final Files sync failure after rename leaves the live path replaced. Date updates its in-memory calendar to that replacement and explicitly reports uncertain durability, asking the user to reopen Date to confirm it persisted. Before-rename failures leave the review open. Host regressions cover duplicate UIDs, provenance persistence and failure phase classification; the CalDAV QEMU gate checks recorded source identity.
