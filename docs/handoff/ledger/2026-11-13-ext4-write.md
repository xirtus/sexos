# ext4 write: extents, directories, rename, truncate, remove; e2fsck clean

Workstream E, slice E7 of `docs/handoff/DAILY_DRIVER_NEXT_100_SLICES.md`.

- `crates/sex-volumes/src/ext4/write.rs`: ext4 volumes with extents are now read-write. It covers
  create, write (holes, odd offsets, unwritten extents made written), truncate (both ways, tail
  zeroed), mkdir, remove (files and empty dirs, hard links counted), and rename across folders
  (`..` and link counts kept). Extent trees are rebuilt at whatever depth is needed, reusing their
  blocks.
- With metadata_csum, every block it writes carries its crc32c: inodes, group descriptors,
  bitmaps, directory tails, extent blocks and the superblock. Allocation moves the itable_unused
  mark.
- The journal is left clean and untouched; each call writes straight to place, then descriptors and
  the superblock.
- Kept read only: ext2/3, a journal needing replay, quota, bigalloc, an orphan file in use, crc16
  group checksums, and an error state.
- Not written to yet: htree directories (removes work, new names are refused), inline-data,
  encrypted or casefold folders, and groups whose bitmaps were never initialised.
- `sexfiles` stamps volume writes with the civil clock (`set_now`, which nothing called before).
- Host: `tests/volumes_ext4_write.rs` (in `volumes_host_gate.sh`):
  - Workloads of 300 to 400 random steps on 4K, 1K, no-csum and 64bit volumes, against a model.
  - A 9,000-extent file (tree depth 2).
  - 400 names in one folder, and a disk filled to NoSpace.
  - `e2fsck -fn` is clean every 50 steps, and `debugfs cat` matches the model.
- Gate: `scripts/files_ext4_gate.py`:
  - A mkfs.ext4 USB stick gets a folder made on it, a file written, a Linux file appended to and a
    file moved into the folder, then it is unmounted.
  - On the host, `e2fsck -fn` is clean and `debugfs` reads every file back.
