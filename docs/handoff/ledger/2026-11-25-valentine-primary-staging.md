# Valentine primary staging prerequisite — 2026-11-25

- Gap: the attachment export commits its chosen destination before streaming bytes, so a power cut can leave a visible partial file.
- Change: Files owns a reserved primary SexFS staging namespace. A program may request a ticket only for its granted exact destination. The ticket binds the run, path and new file identity; chunks must be sequential and within the declared length. Files compares the complete byte count and digest, commits staged bytes, then uses SexFS's checked no-clobber move and commit as the sole publish step. A mount removes incomplete stages before new tickets can be issued. The namespace is inaccessible through ordinary file requests, including whole-filesystem grants. Encrypted home and removable volumes fail closed for these operations.
- Evidence: focused SexFS host tests cut each publish write, remount, verify the chosen name is absent or has all bytes, and check an existing chosen name is preserved. A focused `sexfiles` check could not pass its pre-existing build-script requirement for a trusted `moanplug` artifact. Full build, QEMU and screenshot remain for exact-head GitHub CI.
- Limit: Valentine still uses identity-bound direct writes, so it can leave a partial destination after power loss. A follow-up must add encrypted-home staging and unlock recovery, then switch Valentine to the staged protocol. The current ticket is limited to one active export and 4 MiB, matching Valentine's local message limit.
