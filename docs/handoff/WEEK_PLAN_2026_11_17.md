# SexOS week plan, 2026-11-17 to 2026-11-22

Andreas asked for the next wave: memory, bugs, microkernel and the work that makes SexOS a
beautiful, modern, world-class multimedia OS. This plan splits the week into eight
workstreams that run as parallel threads. It is built from master `7fc62f96` (PR #370
merged, CI green), [`DAILY_DRIVER_NEXT_100_SLICES.md`](DAILY_DRIVER_NEXT_100_SLICES.md),
[`COMPRESSED_RAM_PLAN_2026_11_14.md`](COMPRESSED_RAM_PLAN_2026_11_14.md), the feature ledger,
the open issues and the open pull requests.

Binding rules for every workstream:

- [`docs/DESIGN_GUARDRAILS.md`](../DESIGN_GUARDRAILS.md) and [`docs/BRIDGE_LEDGER.md`](../BRIDGE_LEDGER.md):
  the kernel is mechanism only. No drivers, protocols, POSIX or Linux shapes in ring 0.
- Full builds, QEMU gates and long suites run on GitHub CI from a pushed branch, not in the
  cloud container. Host tests and short builds may run locally.
- PRs merge only on green, through auto-merge (master requires the `build` check).
- Themed app names only, and native apps show only SexOS branding.
- Any new self-wait in a BOOT service needs an admission profile in `scripts/check_self_wait.py`.
- ABI changes are named in the PR; regenerate `spec/abi_inputs.sha256` with
  `scripts/update_abi_hashes.sh` (take master's side on conflicts, then rerun).

## 3. Ownership rules for this week

Kernel files are split so two threads never edit the same one. `kernel/src/syscalls/mod.rs`,
`kernel/src/init.rs` and `kernel/src/lib.rs` are shared: each workstream adds at most ~15 lines
there per PR (a dispatch arm or an init call) and rebases often.

| Kernel files | Owner | Line allowance |
| --- | --- | --- |
| `denim.rs`, `ipc/pagefault.rs`, `app_resources.rs`, `app_resource_state.rs`, `program_workers.rs`, `program_frames.rs`, `program_image.rs` | WS1 | +250 |
| `memory/*`, `slab.rs`, `cpu_account.rs` | WS2 | +100 |
| `scheduler*.rs`, `ipc.rs`, `ipc/*` (not `pagefault.rs`), `ipc_ring.rs`, `core_local.rs`, `paging.rs`, `smp.rs`, `apic.rs` | WS4 | +350 |
| everything else | nobody this week (Drag keeps its own) | 0 |

Each PR that grows the kernel says how many lines it adds. The budget stays 22,700.

`servers/silk-shell/src/main.rs` belongs to the shell thread: others add their own module and a
hook of at most ~10 lines in a separate small PR.

## 4. Workstreams

### WS1 Denim compressed RAM and lazy stacks (memory)

Goal: a program set twice the size of RAM finishes instead of being ended, and programs stop
committing 1 MiB of stack they never touch.

- D3: Denim restart ends runs with pages out (with a Shell notice), faults from worker tasks,
  slab compaction and returning store pages, recall when pressure falls.
- D4: Mesh shows compressed memory per program and the machine ratio.
- D5: soak `--inject` includes Denim.
- #306: lazy stack (manifest change: grown pages no longer assumed to be the last `grown`
  entries), with a guard page, default commit 64 KiB.

Done when: `scripts/denim_gate.py` and a new `heaptest` 2x-RAM gate pass in CI at
`SEXOS_GATE_MEMORY` 1 G and 12 G; Mesh gate shows the ratio; a stack overflow ends the program
with a crash record instead of corrupting memory; kernel growth at most 250 lines.

Files: `servers/denim/`, `crates/denim/`, `apps/heaptest/`, `apps/monitor/` (Mesh),
`crates/sex-pdx/src/denim*`, the WS1 kernel files above, `scripts/denim_gate.py`, new gates.

### WS2 Leak hunt, allocators and the 24-hour soak (memory)

Goal: no service or app leaks pages across open/close cycles, every program uses a real
allocator, and one candidate image survives 24 h with fault injection.

- Replace the bump allocators in `crates/silkbar` and `crates/tatami` with talc (as Denim did).
- Leak gate: open and close each catalog program N times; per-service `free_pages` and kernel
  heap/slab use must return to baseline (add kernel heap/slab counters to `SYS_STATS`).
- Fix every leak the gate finds, in the owning server, in small PRs.
- J2 24 h soak with `--inject` on a CI schedule (nightly workflow), report in the ledger.

Done when: leak gate in CI green for all BOOT services and the top 15 programs; 24 h soak
report shows flat `free_pages`; no `BumpAlloc` left outside `apps/qupid` (WS7 retires it).

Files: `crates/silkbar/`, `crates/tatami/`, `crates/sex-app/` (allocator helper),
`kernel/src/memory/*`, `kernel/src/slab.rs`, `kernel/src/cpu_account.rs`,
`scripts/soak_gate.py`, new `scripts/leak_gate.py`, `.github/workflows/soak.yml` (new file).

### WS3 Bugs, fuzz findings and flaky CI

Goal: zero open fuzz bugs, no flaky boot hangs, a faster CI, and a clean tree.

- Fix #281, #282 (`crates/sex-office`, `apps/spreadeagle`), #319, #320, #321
  (`crates/sex-extensions`, the dnr bridge into `crates/sex-shields`), each with a regression test.
- Pre-kernel Limine hangs: find the cause (boot image size, Limine timeout, QEMU flags), fix it,
  and add a gate-harness retry only for a boot that never reaches the kernel entry line.
- Rebase and land #257 (sealed ISO built once, sharded boot gates) or replace it; land or close
  #270 and #91.
- Delete the 92 `*.bak*` files and extend the guardrail test to forbid them under `servers/`,
  `apps/` and `crates/`.

Done when: the five issues are closed by merged PRs; 10 consecutive master CI runs have no
pre-kernel hang; CI wall time measured before and after; the tree has no `.bak` files.

Files: `crates/sex-office/`, `apps/spreadeagle/`, `crates/sex-extensions/`,
`crates/sex-shields/` (dnr input only), `.github/`, `scripts/qemu*`/gate harness,
`scripts/tests/test_kernel_design_guardrails.py`.

### WS4 Microkernel IPC and scheduler fast paths

Goal: close the IPC gap to Linux (#308) and make the scheduler ready for real hardware.

- Same-core direct handoff for synchronous PDX call/reply: the caller's core switches straight
  to the server task without a queue trip (#308).
- 6b: short messages passed in registers on the call/reply path.
- PCID for program rows, so a domain switch does not flush the whole TLB.
- 7b: deadline class for audio and display (Bell, Display, Moan's audio thread) so a busy
  program cannot delay a buffer refill.

Done when: `apps/bench` ipc_roundtrip and null-call numbers (1 core and 4 cores, no-PKU CPU
model) are in the PR and improve at least 3x on ipc_roundtrip; `latency_gate.py` p99 does not
regress; host scheduler tests pass; kernel growth at most 350 lines with a guardrails row.

Files: the WS4 kernel files above, `crates/sex-pdx/src/` (call wrappers only), `apps/bench/`,
`scripts/latency_gate.py`, `scripts/program_bench_gate.py`.

### WS5 Storage, launch and boot speed

Goal: big programs open fast and the desktop appears sooner.

- #307: sexdrive submits several NVMe commands before waiting (QD > 1); sexfiles readahead for
  sequential reads.
- #305: shrink the biggest programs (Assuit, Spreadeagle, Kaleidoscope, Splicy Studio,
  Polyamour): `opt-level`, LTO, strip, shared code splits; and read the program file in one
  pipelined run.
- #309: start sexdrive and sexfiles bring-up in parallel and move the boot self-test off the
  path to the desktop.

Done when: `bench read-large` throughput and Spreadeagle/Kaleidoscope launch time measured
before and after in the PR (target 2x on both); power-on to first program measured; issues
#305, #307 and #309 closed.

Files: `servers/sexdrive/`, `servers/sexfiles/`, `apps/bench/`, `Cargo.toml` profiles and
`scripts/build_*.sh` for program size, boot service order in the catalog. No kernel files.
