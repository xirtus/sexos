# Chastity canonical vault

The initial round173 custom vault format has been replaced by the user's canonical
Chastity commit37471138. There is one vault implementation: keepass-rs0.17 KDBX,
with TOTP, search, generator and the canonical keyboard model. New vaults use
KDBX4 AES256/Argon2id; existing supported KDBX3.1/4 password vaults can open from
Chastity's own folder as vault.kdbx. Key files, challenge response and legacy KDB
are not offered. Failed parsing never falls back to a different encryption format.

The app is an ordinary std program. Weft supplies the screen paragraph, masked
input view, controls, layout, focus and consent. Typed credentials stay in the
canonical fixed-capacity zeroizing editor; Weft sees stars rather than plaintext
or undo/history copies. Explicit password/TOTP disclosure is drawn transiently
using Weft's shared Painter and its zeroizing text buffer; Lock clears pixels.
Lock/idle/close drop the vault and local editor immediately, then keep the old
zeroized provider session until exact-run/epoch broker revocation acknowledgement.
Unlock and a new provider epoch remain disabled while revocation is pending.

Imported files and KDF metadata are checked before upstream parsing:16MiB file,
64KiB header, Argon2 memory<=64MiB, iterations<=10, parallelism<=4 and memory*passes
<=256MiB-pass; KDBX3 AES rounds<=10million. Canonical new vaults use32MiB/4passes.
The scoped getrandom custom backend covers KDBX salts, IVs and UUIDs and uses only
CPU RDSEED/RDRAND on SexOS; absent/exhausted hardware fails closed. Host tests use
OS entropy. No timestamp entropy fallback is used for cryptographic operations.

The master password and protected values use zeroizing custody. This is best-effort
owned-buffer hygiene: upstream unprotected metadata and compiler/allocator copies
are not an all-memory erasure guarantee. The implementation does not claim an
out-of-process Shibari service: canonical Keeper remains the app-local custody seam.
Dependencies require the reviewed bounded-decompression/Argon2 cleanup follow-up
before merging. sha2@0.11.1 opt-level="s" and layout shuffling remain required for
the existing forbidden-instruction guard. No kernel changes.

Validation:25 canonical core/UI host tests (including original19) and16 production
live-routing host tests pass. The std guest builds and its key-byte scan passes.
QEMU evidence is pending the actual updated Shell/Files image. The canonical
program_chastity_gate.py retains probe, create/add/TOTP, wrong-password refusal,
search/copy refusal and persisted-vault reboot coverage. Live routing is detailed
in CHASTITY_AUTOFILL_2026_11_14.md. No merge until all relevant CI passes.
