# Velvet: original Weft games, ChatGPT round 174

Run `run velvet`. The shared Weft toolkit supplies every control and all drawing,
focus handling and accessibility. There are no copied assets or external game
engines. This dependency PR builds against Weft PR #220; it changes no toolkit,
shell, kernel or Claude-owned application files.

## Games

- **Snags:** 6x6 minefield with six snags. Reveal all 30 safe squares to win.
  The first revealed square is guaranteed safe, zeroes flood open and flags block
  accidental reveals. Check the flag box or press Ctrl+F to switch between flagging
  and revealing. Losing exposes every snag. New Game clears flags and changes the
  layout. The seed affects only entertainment, not security.
- **Mingle:** 4x4 number merging. Slide with arrow keys or direction buttons. Each
  tile merges at most once per move; only a changed board spawns a new 2 or 4. Reach
  2048 to win; a full board without a legal move loses. Score counts merged values.
- **Twin Flames:** eight shuffled letter pairs. Pick two squares; matching pairs
  stay visible. A mismatch stays visible until the next choice, so there is no
  timer or race to remember it. Match all eight pairs to win. Turns count pairs
  attempted, not individual flips.

Click the game names, or press Ctrl+1 / Ctrl+2 / Ctrl+3. Ctrl+N restarts the current
game. Switching games preserves each game's progress. Tab and Shift+Tab reach all
buttons; Enter or Space activates the focused button. Mingle additionally uses
arrow keys. F11 closes through the normal Shell lifecycle.

The game grid fits the default 640x400 program window. Hidden snags and cards are
not placed in accessibility names, tooltips or serial diagnostics. All art is
original text, numbers and standard Weft controls; no bespoke widget renderer.
Scores and games are currently in-memory only; there is no save file or network.

## Validation

`cargo test --locked -p velvet --no-default-features` runs twelve tests covering
first-click safety across 240 board starts, exact snag count, flags, adjacency,
win/loss, merge direction/score/no-op behavior, matching rules, actual Weft pointer
and keyboard input, restart, and the 640x400 grid bounds.

`cargo run --locked -p velvet --no-default-features --example preview -- OUTDIR`
renders the exact three Weft interfaces as PPM images for host visual inspection.
These images prove host layout only, not guest playback or input routing.

`RUSTFLAGS='-C relocation-model=pic -C link-arg=-pie' cargo build --locked --release
-Z build-std=core,compiler_builtins,alloc
-Z build-std-features=compiler-builtins-mem --target x86_64-sex-app.json -p velvet`
builds the guest. `scripts/key_bytes.py` checks the loader's forbidden instructions;
`build.rs` supports the normal build trace's deterministic layout retries.

`scripts/velvet_gate.py --iso sexos-v1.0.0.iso --source-disk BLANK.img --out OUTDIR`
installs Velvet, launches it through Spindle, uses real pointer input to reveal and
flag a square, restarts by keyboard, plays Mingle with arrow keys, flips two cards,
restarts Twin Flames, verifies nonblank screenshots of all three games and closes
through Shell. It retains `result.json`, PPMs and serial output. CI must pass this
gate before merge; a host render or successful guest compile is not a QEMU pass.
