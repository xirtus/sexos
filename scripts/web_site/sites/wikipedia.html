In computer science, a microkernel is the near-minimum amount of software that can provide the mechanisms needed to build an operating system.[1] Those mechanisms are low-level address space management, thread management, and inter-process communication (IPC). Everything else, from device drivers to file systems, runs outside the kernel as ordinary programs called servers.

Because a fault in a server cannot corrupt the kernel, a microkernel system can restart a failed driver while the rest keeps running.[2]

History

Layers of a microkernel system: the kernel at the bottom, servers above it, applications on top.

The idea of keeping the kernel small dates to the late 1960s. Later research systems showed that careful design of message passing makes the cost of crossing between servers small enough for daily use.

Design

Messages

Servers talk by sending messages through the kernel. A message can carry a small amount of data directly, or grant the receiver access to a page of memory.

Servers

Each server owns one job. A file server, for example, answers requests to open and read files and asks a disk driver server for blocks.

Performance

Early microkernels were slow because every request crossed into the kernel twice. Modern designs keep these crossings short, and a single address space with hardware memory keys can avoid copying altogether.[3]
